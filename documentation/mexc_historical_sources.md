# Источники исторических данных по бессрочным фьючерсам MEXC

Цель: собрать первые сутки торгов (минутные OHLCV, объёмы, при возможности движения сделок) по 500 контрактам, вышедшим на MEXC первыми среди бирж.

## 1. Подбор поставщиков данных

| Поставщик | Покрытие MEXC | Что получить | Стоимость / лицензия | Комментарии |
|-----------|---------------|--------------|-----------------------|-------------|
| Kaiko | Фьючерсы и свопы MEXC c тикерной лентой, минутные/секундные свечи | Исторические OHLCV, торги, открытый интерес (по запросу) | Enterprise; прайс индивидуальный, есть триалы | Надёжный источник для backfill. Проверить, есть ли свечи с даты листинга. |

Дополнительно стоит запросить у **MEXC Data Services** собственные исторические дампы фьючерсов: биржа иногда продаёт архивы напрямую.

## 2. Процедура сбора данных

1. **Сформировать список целевых контрактов.**
   - Вытянуть актуальный перечень символов с `https://contract.mexc.com/api/v1/contract/detail`.
   - Для каждого контракта собрать `openingTime`/`createTime`, `indexOrigin`, `baseCoin`, `quoteCoin`.
   - Отфильтровать по признаку «индекс только MEXC» (наш текущий эвристический критерий первичности). При необходимости расширить логикой из внешних источников.

2. **Запросить исторические свечи у выбранных провайдеров.**
   - Составить CSV/JSON со списком символов и датами запуска.
   - Направить поставщику запрос на выгрузку минутных OHLCV и сделок за первые 24 часа после `openingTime`.
   - Уточнить временную зону/формат (UTC), наличие пропусков, точность объёмов.

3. **Проверить эксклюзивность листинга.**
   - Собрать календарь листингов (spot и futures) на крупных биржах: Binance, Bybit, OKX, Bitget, KuCoin, Gate.io.
   - Использовать API сторонних агрегаторов (Messari, Coindar, CryptoRank) или ручные пресс-релизы.
   - Для каждого токена убедиться, что дата листинга на MEXC не позже других площадок (или зафиксировать исключения).

4. **Собрать данные в единый формат.**
   - Для каждого контракта: минутные свечи (timestamp, open, high, low, close, volume, notional) + метаданные (symbol, listing_time_utc, источник, статус проверки эксклюзивности).
   - Сохранить в Parquet/JSON для аналитики и в CSV для быстрой выгрузки.

5. **Построить контроль качества.**
   - Проверить, что первые сутки полностью покрыты (1440 ± несколько минут в зависимости от реальной торговой активности).
   - Выявить отклонения (нет данных, подозрительные нули, резкие скачки) и запросить перерасчёт у поставщика.

## 3. Отделить задачу на «прошлое» и «будущее»

- **Backfill (прошлое):** приобрести или найти архивы у сторонних провайдеров. Это обеспечит покрытие старых контрактов и приблизит цель «500 листингов».
- **Forward monitor (будущее):** оставить скрипт `scripts/mexc_listing_monitor.py` для автоматического сбора новых листингов, чтобы не упустить свежие первые сутки.

## 4. Практические рекомендации

- **Бюджетирование:** оцените стоимость подписки/дампов. При необходимости ограничьте список символов (например, только с 2024 года) или уменьшите набор метрик.
- **Лицензирование:** уточните у поставщика права на хранение, распространение и публикацию данных.
- **Инфраструктура:** организуйте пайплайн (Airflow, cron, серверless) для регулярного обновления данных и резервного копирования.
- **Документирование:** фиксируйте источник, дату получения и контактное лицо по каждому набору, чтобы проще обновлять или дополнять данные позже.

Такой план позволит закрыть дефицит исторических данных по старым листингам и одновременно продолжать собирать свежую статистику, пока она доступна на MEXC.
